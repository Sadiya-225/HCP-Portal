# Hyderabad City Police — Citizen Services Portal

A Next.js 16 (App Router, Cache Components) portal with email/password
authentication powered by [Better Auth](https://www.better-auth.com) on
PostgreSQL via Drizzle ORM. Designed to run in Docker Compose behind Caddy
with automatic HTTPS.

## Architecture

| Piece | Choice |
| --- | --- |
| Web framework | Next.js 16 App Router + Cache Components, standalone output |
| Auth | Better Auth 1.7 (`/api/auth/[...all]`), DB-backed rate limiting |
| Database | PostgreSQL 17 + Drizzle ORM (`pg` driver) |
| Migrations | drizzle-kit generated SQL, applied by a one-shot `migrate` service |
| TLS / edge | Caddy 2 with automatic HTTPS |
| Password reset email | Nodemailer over SMTP — **disabled unless explicitly configured** |

## Local development

Two ways to run locally.

### A. Direct npm dev (zero-setup)

On a fresh clone, with no `.env`, Docker, or system PostgreSQL:

```bash
npm ci
npm run dev
```

`npm run dev` automatically:

1. Generates a gitignored `.env.local` with cryptographically random
   secrets (never printed),
2. Starts an embedded, loopback-only (`127.0.0.1:54329`) PostgreSQL 17
   instance persisted at `.data/postgres`,
3. Applies the checked-in Drizzle migrations,
4. Starts Next.js at `http://localhost:3000`.

To use your own external PostgreSQL instead, create `.env.local` with
`DEV_EMBEDDED_POSTGRES=false` and real `DATABASE_URL` /
`DATABASE_MIGRATION_URL` values. Required env vars validated at runtime
(`lib/env.ts`): `DATABASE_URL`, `BETTER_AUTH_SECRET` (min 32 chars,
`openssl rand -base64 32`), `BETTER_AUTH_URL`; optional `TRUSTED_ORIGINS`,
`DB_POOL_MAX` (1–50), and the SMTP/`PASSWORD_RESET_ENABLED` block.

`npm run dev:next` starts raw `next dev` and expects a database and env
to already be running/configured. `npm run db:migrate` applies
migrations manually (loads `.env.local`/`.env`).

The embedded database is **development-only** — production/Compose still
runs the PostgreSQL 17 container with least-privilege roles.

> **npm install-script approvals:** this repo pins `allowScripts`
> approvals (see `package.json`) for the install scripts it needs,
> including the Windows `@embedded-postgres/windows-x64` binary. On
> non-Windows platforms npm may report a pending
> `@embedded-postgres/<platform-arch>` postinstall — review and approve
> the matching package (`npm approve-scripts <pkg>`) if `npm run dev`
> cannot find database binaries.

### B. Full Compose stack locally

Requires Docker with the Compose plugin. Edit `.env` with real values
(`DOMAIN`, `ACME_EMAIL`, all passwords, `BETTER_AUTH_SECRET`,
`BETTER_AUTH_URL=https://${DOMAIN}`), then:

```bash
docker compose up -d --build
docker compose ps        # db healthy, migrate exited 0, app healthy
```

The site is served by Caddy at `https://${DOMAIN}` — automatic HTTPS
needs a real domain whose DNS points at the machine and ports 80/443
open. For a pure local HTTP-only check, prefer option A; Compose is the
production-shaped path.

Keep `NEXT_TELEMETRY_DISABLED=1` set in `.env` (it is already set in
the Dockerfile).

## Scripts

| Command | Purpose |
| --- | --- |
| `npm run dev` | Dev bootstrap: env + embedded PostgreSQL + migrations + Next |
| `npm run dev:next` | Raw `next dev` (DB/env must already exist) |
| `npm run build` / `start` | Production build / standalone server |
| `npm run lint` | ESLint |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | Vitest suite |
| `npm run auth:schema` | Regenerate `db/schema.ts` via the official Better Auth CLI |
| `npm run db:generate` | Generate a new migration from `db/schema.ts` |
| `npm run db:migrate` | Apply migrations (`DATABASE_MIGRATION_URL ?? DATABASE_URL`) |

## Database & migrations

- `db/schema.ts` is the official Better Auth schema (user, session, account,
  verification, rate_limit) generated by the official Better Auth CLI.
  To regenerate after changing auth options: `npm run auth:schema`,
  inspect the diff, then `npm run db:generate` for the SQL migration.
- `drizzle.config.ts` reads `DATABASE_MIGRATION_URL ?? DATABASE_URL` so the
  CLI can run without app env modules.
- Never use `drizzle-kit push`/`drop` — always `db:generate` + `db:migrate`.
- In Docker, a least-privilege `migrate` role owns the schema; the app role
  has DML only (see `docker/postgres/init/01-roles.sh`).

## Authentication surfaces

- `POST/GET /api/auth/*` — Better Auth handler (sign-up, sign-in, sign-out,
  password reset). No custom auth endpoints exist.
- `GET /api/me` — current session user only (`401` otherwise); query/body
  parameters are never trusted.
- `GET /api/health` — DB probe returning `{ "status": "ok" }`.
- Pages: `/`, `/register`, `/login`, `/logout`, `/forgot-password`,
  `/reset-password`, `/dashboard` (protected server-side).

Rate limiting is enforced by Better Auth in the database: 5/min for sign-in
and sign-up, 3/5min for reset requests, 5/5min for reset submits (100/min
global).

## Password reset emails

`PASSWORD_RESET_ENABLED` defaults to `false`: Better Auth still behaves
normally but no email is sent and nothing is logged. To enable delivery, set
`PASSWORD_RESET_ENABLED=true` **and** all of `SMTP_HOST`, `SMTP_PORT`,
`SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. TLS 1.2+ is
required (`SMTP_SECURE=true` for implicit TLS, otherwise STARTTLS).

## Production deployment

See `docs/DEPLOYMENT.md` for a complete OCI Always Free deployment guide and
`docs/SECURITY_AND_PRIVACY.md` for the security/privacy model.

Quick reference:

```bash
docker compose build

docker compose logs -f app
```
